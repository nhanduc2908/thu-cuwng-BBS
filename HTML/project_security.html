01 / Security scope

Phạm vi & giả định bảo vệScope & protection assumptions

Deployment

Ứng dụng cục bộLocal application

PetCare chạy trên máy Windows, lưu dữ liệu trong SQLite cục bộ và không yêu cầu web backend. Bảo vệ máy, tài khoản Windows, thư mục database và các bản backup là một phần của bảo mật tổng thể.PetCare runs on Windows, stores data in local SQLite, and does not require a web backend. Securing the machine, Windows account, database directory, and backups is part of the overall security boundary.

Information

Dữ liệu nhạy cảm vận hànhSensitive operational data

Cơ sở dữ liệu có thể chứa thông tin liên hệ khách hàng, hồ sơ vật nuôi, ghi chú sức khỏe, giao dịch và tài khoản nhân viên. Chỉ thu thập, xem, xuất và chia sẻ những gì công việc yêu cầu.The database may contain customer contact details, pet profiles, health notes, transactions, and staff accounts. Collect, view, export, and share only what the task requires.

Threat boundary

Không phải mô hình SaaSNot a SaaS threat model

Tài liệu tập trung vào rủi ro máy cục bộ, tài khoản nội bộ, thao tác trái quyền, mất/hỏng file database và rò rỉ backup; không tuyên bố kiểm soát bảo mật mạng/cloud đa chi nhánh.This review focuses on local-machine, internal-account, unauthorized-action, database loss/corruption, and backup disclosure risks; it does not claim network/cloud or multi-branch controls.

02 / Implemented controls

Kiểm soát đã xác nhận trong mã nguồnControls confirmed in source

Authentication

Hash mật khẩuPassword hashing

Mã nguồn dùng PBKDF2-HMAC-SHA256 với 600.000 vòng, salt ngẫu nhiên 16 byte và so sánh hash theo thời gian hằng số. Mật khẩu thường tối thiểu 10 ký tự; giá trị tạm admin là ngoại lệ khởi tạo và phải đổi khi đăng nhập đầu.Source uses PBKDF2-HMAC-SHA256 with 600,000 iterations, a random 16-byte salt, and constant-time hash comparison. Normal passwords require at least 10 characters; the temporary admin credential is a bootstrap exception and must be changed at first sign-in.

app/modules/auth/security.py

Authorization

Quyền theo vai tròRole-based permissions

Các vai trò ADMIN, MANAGER, VETERINARIAN, CAREGIVER và SALES có tập quyền khác nhau. Các thao tác ghi trong database yêu cầu permission tương ứng; ẩn menu chỉ là hỗ trợ giao diện, không thay thế kiểm tra nghiệp vụ.ADMIN, MANAGER, VETERINARIAN, CAREGIVER, and SALES have distinct permission sets. Database writes require the corresponding permission; hiding a menu is a UI aid, not a substitute for business-layer checks.

app/modules/auth/constants.py, app/database.py

Auditability

Audit có chọn lọcSelected audit events

Audit log lưu actor, action, entity và thời điểm cho một số sự kiện. SQLite trigger chặn UPDATE/DELETE qua connection ứng dụng; audit không ghi mọi click và không phải kho log chống giả mạo nếu người dùng kiểm soát file/máy.Audit logs store actor, action, entity, and time for selected events. SQLite triggers reject UPDATE/DELETE through the application connection; audit does not record every click and is not tamper-proof against someone controlling the file or host.

app/modules/audit/repository.py, app/database.py

Backup

Sao lưu theo yêu cầuOn-demand backup

Backup dùng SQLite backup API, yêu cầu quyền settings.manage, không ghi đè file đích đã tồn tại và audit tên file. Giao diện hiện không có luồng restore hoặc lịch backup tự động.Backup uses SQLite's backup API, requires settings.manage, refuses an existing destination, and audits the filename. The current UI has no restore workflow or automatic backup schedule.

app/database.py, app/ui/notifications/page.py

03 / Gaps & residual risks

Khoảng trống cần quản trịGaps requiring operational controls

Account lifecycle

Thông tin khởi tạo mặc địnhDefault bootstrap credential

Tài khoản admin tạm dùng mật khẩu mặc định đã biết. Không dùng ngoài môi trường thiết lập; đổi ngay, giới hạn người biết và không gửi qua kênh không an toàn. Chưa có MFA theo README.The bootstrap admin uses a known default password. Do not use it beyond setup; rotate immediately, restrict who knows it, and never send it over an unsafe channel. MFA is not provided per the README.

At-rest protection

Mã hóa fileFile encryption

Không thấy lớp mã hóa database/backup ở cấp ứng dụng. Dùng mã hóa toàn đĩa do hệ điều hành/tổ chức quản lý, khóa màn hình, quyền NTFS tối thiểu và vùng backup được bảo vệ.No application-level database/backup encryption is evident. Use OS/organization-managed full-disk encryption, screen locking, least-privilege NTFS permissions, and a protected backup location.

Recovery

Khôi phục chưa được cung cấp trong UIRestore is not provided in the UI

Tạo được backup không chứng minh khôi phục thành công. Chủ dữ liệu cần lưu bản sao tách khỏi máy, xác định thời hạn lưu và diễn tập restore trên bản sao an toàn trước khi pilot.Creating a backup does not prove recovery works. The data owner should keep an off-machine copy, define retention, and rehearse restoration from a safe copy before a pilot.

Data handling

Xuất & chia sẻExport & sharing

CSV/PDF hoặc file backup có thể chứa dữ liệu cá nhân/vận hành. Cần xác nhận người nhận, đường truyền, quyền truy cập và xóa bản tạm theo chính sách nội bộ.CSV/PDF exports or backups may contain personal/operational data. Verify recipients, transfer method, access, and deletion of temporary copies under internal policy.

04 / Operating checklist

Checklist trước khi dùng dữ liệu thậtBefore using real data

  1. Cài từ nguồn tin cậy, rà soát revision và chạy toàn bộ test trên đúng bản dự định sử dụng.Install from a trusted source, review the revision, and run the complete test suite on the intended build.
  2. Đổi admin mặc định; tạo tài khoản riêng; gán vai trò tối thiểu cần thiết; vô hiệu hóa tài khoản nghỉ việc.Change the default admin password; use named accounts; grant least privilege; disable accounts when staff leave.
  3. Bảo vệ máy Windows, database và thư mục backup; không dùng tài khoản chia sẻ nếu có thể tránh.Secure the Windows host, database, and backup directory; avoid shared accounts where possible.
  4. Tạo backup theo lịch vận hành, kiểm tra file được tạo và diễn tập restore bằng quy trình được phê duyệt.Create backups under an operational schedule, verify the file, and rehearse restore using an approved procedure.
  5. Dùng dữ liệu demo cho thuyết trình; che/loại bỏ dữ liệu nhận dạng trong ảnh chụp và báo cáo chia sẻ.Use demo data for presentations; redact or remove identifiers from shared screenshots and reports.
  6. Ghi nhận sự cố, giữ bản sao log/database theo quy trình, giới hạn người xử lý và đổi thông tin xác thực liên quan.Record incidents, preserve log/database copies under procedure, restrict responders, and rotate affected credentials.
